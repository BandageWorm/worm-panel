## 新增需求

### 需求：Nginx 站点列表

系统应扫描 Nginx sites-enabled 目录列出所有站点配置。

#### 场景：获取站点列表
- **当** 已认证用户发送 GET /api/nginx/sites
- **则** 系统返回站点列表（名称、状态、域名），面板自身配置标记为只读

#### 场景：获取单个站点配置
- **当** 已认证用户发送 GET /api/nginx/sites/:name
- **则** 系统返回该站点的完整配置内容

### 需求：反代站点管理

系统应支持通过模板创建、更新、删除 Nginx 反代站点。

#### 场景：创建反代站点
- **当** 已认证用户发送 POST /api/nginx/sites，携带域名、目标端口、备注
- **则** 系统生成 Nginx 反代配置，执行 nginx -t 校验后启用

#### 场景：更新站点配置
- **当** 已认证用户发送 PUT /api/nginx/sites/:name，携带配置内容
- **则** 系统写入临时文件，nginx -t 校验成功后覆盖正式文件并 reload

#### 场景：更新失败回滚
- **当** nginx -t 校验失败
- **则** 系统不覆盖正式文件，返回错误信息

#### 场景：删除站点
- **当** 已认证用户发送 DELETE /api/nginx/sites/:name
- **则** 系统删除对应配置文件并 reload nginx

#### 场景：删除面板自身配置
- **当** 用户尝试删除面板自身反代配置（panel.conf）
- **则** 系统拒绝操作，返回禁止删除错误

### 需求：Nginx 操作

系统应支持手动校验配置和重新加载 Nginx。

#### 场景：校验配置
- **当** 已认证用户发送 POST /api/nginx/validate
- **则** 系统执行 nginx -t 并返回校验结果

#### 场景：重新加载
- **当** 已认证用户发送 POST /api/nginx/reload
- **则** 系统执行 nginx -s reload 并返回结果

### 需求：配置备份

系统应在修改 Nginx 配置前自动备份，保留最近 30 份。

#### 场景：自动备份
- **当** 系统即将修改 Nginx 配置文件
- **则** 系统先将当前配置备份到 data/backups/nginx/，文件名包含时间戳

#### 场景：查看备份列表
- **当** 已认证用户发送 GET /api/nginx/backups
- **则** 系统返回备份列表（文件名、时间）

### 需求：Nginx 管理页面 UI

系统应在 /#/nginx 提供 Nginx 管理页面。

#### 场景：查看站点列表
- **当** 已认证用户导航到 /nginx
- **则** 页面显示站点列表（名称、状态、域名），面板配置标记为只读

#### 场景：添加反代站点
- **当** 用户填写域名、目标端口、备注并提交
- **则** 系统创建反代配置

#### 场景：编辑配置
- **当** 用户点击编辑站点
- **则** 页面显示配置文本编辑器，支持语法高亮

#### 场景：删除站点
- **当** 用户点击删除并确认
- **则** 系统删除站点配置
