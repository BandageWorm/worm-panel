## 新增需求

### 需求：笔记存储

笔记以 .md 文件形式存储在 data/notes/ 目录，支持文件系统直接读写。

#### 场景：笔记目录初始化
- **当** 面板首次启动
- **则** 系统确保 data/notes/ 目录存在

### 需求：笔记列表

系统应按更新时间排序返回笔记列表。

#### 场景：获取笔记列表
- **当** 已认证用户发送 GET /api/notes
- **则** 系统返回笔记列表，包含文件名和更新时间

### 需求：笔记读写

系统应支持笔记的创建、读取、更新、删除操作。

#### 场景：读取笔记内容
- **当** 已认证用户发送 GET /api/notes/:name
- **则** 系统返回笔记的 Markdown 内容

#### 场景：创建笔记
- **当** 已认证用户发送 POST /api/notes，携带 name 和 content
- **则** 系统在 data/notes/ 目录创建 .md 文件并返回成功

#### 场景：更新笔记
- **当** 已认证用户发送 PUT /api/notes/:name，携带 content
- **则** 系统更新对应文件内容

#### 场景：删除笔记
- **当** 已认证用户发送 DELETE /api/notes/:name
- **则** 系统删除对应 .md 文件

### 需求：路径穿越防护

系统应校验文件名，防止路径穿越攻击。

#### 场景：非法文件名
- **当** 用户请求包含 ../ 等路径穿越字符
- **则** 系统返回校验错误，拒绝操作

### 需求：笔记管理页面 UI

系统应在 /#/notes 提供 Markdown 笔记管理页面。

#### 场景：查看笔记列表
- **当** 已认证用户导航到 /notes
- **则** 左侧显示笔记列表（文件名、更新时间），右侧显示编辑器

#### 场景：编辑笔记
- **当** 用户点击笔记并编辑内容
- **则** 右侧编辑器实时编辑，分屏预览 Markdown 渲染效果

#### 场景：新建笔记
- **当** 用户点击新建按钮并输入标题和内容
- **则** 系统创建笔记并刷新列表

#### 场景：保存笔记
- **当** 用户点击保存按钮
- **则** 系统更新笔记文件内容

#### 场景：删除笔记
- **当** 用户点击删除按钮并确认
- **则** 系统删除笔记文件并刷新列表

#### 场景：预览模式
- **当** 用户打开笔记
- **则** 默认显示 Markdown 渲染预览，可点击按钮切换到编辑模式
- **则** 预览模式下渲染标题、代码块、表格、引用等 Markdown 语法

#### 场景：导出笔记
- **当** 用户点击导出按钮
- **则** 系统将当前笔记内容导出为 .md 文件下载

#### 场景：导入笔记
- **当** 用户点击导入按钮并选择 .md 文件
- **则** 系统读取文件内容并创建笔记
- **则** 若同名笔记已存在，提示用户确认后覆盖
