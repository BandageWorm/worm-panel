# alerting Specification

## Purpose
让面板在无人查看时也能把异常主动推送到用户手上：支持 Telegram、邮件与通用 webhook 三种投递方式，按可配置的规则判定异常，并通过冷却与恢复通知避免刷屏、确认故障已消除。

## Requirements

### Requirement: 通知通道配置与凭据保护

系统 SHALL 支持配置多个通知通道，每个通道可独立启用与停用。

#### Scenario: 多通道同时启用
- **WHEN** 用户同时启用 Telegram、邮件与 webhook
- **THEN** 每条告警向三个通道都投递一次

#### Scenario: 凭据只写不读
- **WHEN** 已认证用户读取告警通道配置
- **THEN** 系统只返回每个通道是否已配置，不返回 botToken、邮箱密码或完整 webhook 地址

#### Scenario: 修改凭据
- **WHEN** 用户提交通道配置时凭据字段留空
- **THEN** 系统保留原有凭据不变，只更新其余字段

#### Scenario: 未配置任何通道
- **WHEN** 没有任何通道处于启用且已配置状态
- **THEN** 系统仍执行规则判定与历史记录，但不尝试投递，并在页面上提示"未配置通知通道"

### Requirement: Telegram 通道

系统 SHALL 通过 Telegram Bot API 投递消息，并允许自定义 API 基础地址。

#### Scenario: 使用默认地址投递
- **WHEN** 用户填写 bot token 与 chat id 且未填写自定义地址
- **THEN** 系统向官方 API 地址发送文本消息

#### Scenario: 使用自定义地址投递
- **WHEN** 用户填写了自定义 API 基础地址（例如反代地址）
- **THEN** 系统向该地址发送消息，用于直连不通的环境

#### Scenario: Token 无效
- **WHEN** Telegram 返回鉴权失败
- **THEN** 系统记录该次失败的响应原文，并在通道状态中标记为"最近一次投递失败"

### Requirement: 邮件通道

系统 SHALL 通过 SMTP 投递告警邮件，并限制为可用的加密端口。

#### Scenario: 通过 SSL 端口投递
- **WHEN** 用户配置端口 465
- **THEN** 系统以隐式 TLS 建立连接并投递邮件

#### Scenario: 通过 STARTTLS 端口投递
- **WHEN** 用户配置端口 587
- **THEN** 系统以 STARTTLS 升级连接后投递邮件

#### Scenario: 端口不在允许范围
- **WHEN** 用户配置 465/587 以外的端口
- **THEN** 系统拒绝保存并说明原因（避免被云厂商封禁 25 端口导致投递静默失败）

#### Scenario: 自签证书服务器
- **WHEN** 用户启用了"允许不安全证书"选项
- **THEN** 系统跳过证书校验完成投递，并在页面上对该选项给出风险提示

#### Scenario: 多个收件人
- **WHEN** 用户填写多个收件地址
- **THEN** 系统向全部收件人投递同一封邮件

### Requirement: Webhook 通道

系统 SHALL 支持向任意 HTTP 端点投递告警，允许自定义请求方法与请求体模板。

#### Scenario: 默认请求体
- **WHEN** 用户只填写 URL 而未自定义请求体
- **THEN** 系统以 POST 发送包含标题与内容的 JSON 请求体

#### Scenario: 自定义模板
- **WHEN** 用户在请求体中使用了模板变量（标题、级别、内容、目标、取值、时间）
- **THEN** 系统在发送前用当次告警内容替换这些变量

#### Scenario: 预设服务
- **WHEN** 用户选择 Bark、Server 酱、企业微信或钉钉预设
- **THEN** 系统自动填入该方法所需的 URL 形式与请求体结构，用户只需补填密钥

#### Scenario: 响应判定
- **WHEN** 目标端点返回 2xx
- **THEN** 该次投递视为成功；返回其他状态码、超时（10 秒）或连接失败均视为失败，且不跟随重定向

### Requirement: 通道测试与并行投递

系统 SHALL 允许对单个通道发送测试消息，并在正式投递时隔离各通道结果。

#### Scenario: 发送测试消息
- **WHEN** 用户在某通道上点击"发送测试"
- **THEN** 系统立即投递一条测试消息并返回成功或失败原因与实际耗时

#### Scenario: 单通道失败不影响其他
- **WHEN** 多通道投递中某一个通道失败
- **THEN** 其余通道照常完成投递，且各通道结果分别记录

### Requirement: 阈值告警规则

系统 SHALL 支持对资源指标设置带阈值的告警规则，并可逐条启用或停用。

#### Scenario: 磁盘使用率超限
- **WHEN** 磁盘使用率超过配置阈值（默认 90%）
- **THEN** 系统产生一条告警

#### Scenario: 内存持续超限
- **WHEN** 内存使用率连续超过阈值（默认 90%）达 5 分钟
- **THEN** 系统产生一条告警；短时毛刺不触发

#### Scenario: 负载持续超限
- **WHEN** 1 分钟平均负载连续超过"核心数 × 2"达 10 分钟
- **THEN** 系统产生一条告警

#### Scenario: 月流量接近配额
- **WHEN** 已配置月度配额且用量超过配额的 80%
- **THEN** 系统产生一条警告级告警；超过 95% 时产生严重级告警

#### Scenario: 规则停用
- **WHEN** 某条规则被停用
- **THEN** 该规则不再产生新告警，但历史记录保留

### Requirement: 事件告警规则

系统 SHALL 在关键事件发生时产生告警。

#### Scenario: 证书临期
- **WHEN** 某证书剩余有效期降至 14 天或 7 天
- **THEN** 系统分别产生一次对应级别的告警

#### Scenario: 服务异常
- **WHEN** nginx 未运行或配置校验失败，或面板自身连续两次健康检查失败
- **THEN** 系统产生告警

#### Scenario: PM2 进程异常
- **WHEN** 存在状态为 errored 的 PM2 进程
- **THEN** 系统产生告警并指明进程名

#### Scenario: 备份失败
- **WHEN** 云备份的最近一次同步结果为失败
- **THEN** 系统产生告警并附带错误摘要

#### Scenario: 定时任务失败
- **WHEN** 某条计划任务的最近一次执行结果为非零退出码
- **THEN** 系统产生告警并指明任务名与退出码

### Requirement: 冷却与恢复通知

系统 SHALL 按规则与目标维度抑制重复告警，并在异常消除后发送恢复通知。

#### Scenario: 冷却期内抑制重复
- **WHEN** 同一规则对同一目标在冷却期内再次命中
- **THEN** 系统更新内部状态但不重复投递

#### Scenario: 冷却键按目标独立
- **WHEN** 多张证书或多台服务在同期触发同一规则
- **THEN** 每个目标各自独立判定与冷却，不互相抑制

#### Scenario: 异常恢复
- **WHEN** 判定条件从命中转为不再命中
- **THEN** 系统发送一条恢复通知，说明该异常已消除

#### Scenario: 重启后状态延续
- **WHEN** 面板服务重启
- **THEN** 冷却状态与正在告警的条目从持久化文件恢复，不会因重启而重复发送或丢失恢复通知

### Requirement: 投递失败处理

系统 SHALL 对投递失败进行有限重试，并将最终失败结果保留下来。

#### Scenario: 首次失败后重试
- **WHEN** 某次投递失败
- **THEN** 系统间隔后重试一次

#### Scenario: 重试仍失败
- **WHEN** 重试后依然失败
- **THEN** 该条消息进入待发队列，在后续周期继续尝试，达到上限后放弃并在历史中标记为失败

#### Scenario: 失败不静默
- **WHEN** 任一条告警的最终投递结果为失败
- **THEN** 该失败在告警历史与通道状态中可见，包含通道名、时间与错误原文

### Requirement: 告警历史

系统 SHALL 保存最近的告警投递记录供事后查阅。

#### Scenario: 记录字段
- **WHEN** 系统产生并投递一条告警
- **THEN** 历史中记录时间、规则、级别、目标、消息摘要、各通道结果与耗时

#### Scenario: 容量限制
- **WHEN** 历史记录数量超过上限（200 条）
- **THEN** 系统按时间淘汰最早记录

#### Scenario: 查看历史
- **WHEN** 用户在告警页面查看历史
- **THEN** 页面按时间倒序列出记录，并可展开查看各通道的失败原因

### Requirement: 告警页面

系统 SHALL 在日志中心页面（`/logs?tab=alerts`）提供告警管理标签页，旧地址 `/alerts` 重定向到该标签页。

#### Scenario: 页面内容
- **WHEN** 用户打开日志中心的告警标签页
- **THEN** 页面包含通道配置区、规则列表（含开关与阈值）与告警历史三个区域

#### Scenario: 调整阈值
- **WHEN** 用户修改某条规则的阈值或冷却期并保存
- **THEN** 新配置立即生效，无需重启面板

#### Scenario: 手机端访问
- **WHEN** 用户在窄屏设备上访问告警页面
- **THEN** 三个区域以单列纵向排列，表单与表格可正常操作
