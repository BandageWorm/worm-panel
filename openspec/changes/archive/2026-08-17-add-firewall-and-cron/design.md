## Context

Worm Panel 当前缺少防火墙管理和计划任务管理功能。用户管理 ufw 规则和 crontab 条目都需要 SSH 手动操作。项目已有成熟的模块化模式：后端 `services/` 封装系统命令 + `routes/` 暴露 REST API，前端 `views/` 对应独立页面。两个新模块沿用此模式。

当前项目中 nginx 模块使用 `execFileAsync` 封装系统命令并自动 sudo 重试，这个模式将被复用到 ufw 命令执行中。

## Goals / Non-Goals

**Goals:**
- 通过 Web 界面管理 ufw 防火墙规则（状态、规则增删）
- 通过 Web 界面管理 crontab 计划任务（CRUD、立即执行、历史记录）
- 保护面板自身端口不被误删
- 计划任务执行历史持久化存储

**Non-Goals:**
- 不支持 iptables 底层操作或复杂 NAT/转发
- 不管理非面板创建的 cron 条目（仅只读展示）
- 不支持 firewalld（只支持 ufw）
- 不做秒级调度或任务依赖编排
- 不做实时推送（前端手动刷新）

## Decisions

### 1. 防火墙命令封装方式

**选择**: 使用 `child_process.execFile` + sudo 自动重试模式（与 nginx 模块一致）

**备选**: 使用 node-ufw 第三方库  
**理由**: ufw 命令行接口简单稳定，直接封装避免引入额外依赖，且与项目现有模式一致

### 2. ufw 输出解析策略

**选择**: 解析 `ufw status numbered` 的文本输出

**格式示例**:
```
[ 1] 22/tcp    ALLOW IN    Anywhere
[ 2] 80/tcp    ALLOW IN    Anywhere
```

**理由**: `ufw status numbered` 输出格式稳定，包含编号可直接用于删除操作。相比解析 JSON（ufw 不支持），文本解析足够可靠。

### 3. 面板端口保护机制

**选择**: 后端双重校验 — 读取当前面板配置端口，删除规则时检查目标端口是否是面板端口，若是则拒绝

**理由**: 防止用户锁死面板访问。前端也做 UI 层面的禁用，但安全校验必须在后端。

### 4. Cron 任务标识方式

**选择**: 使用注释行标记面板管理的任务

```cron
# worm:<id>:<name>
0 3 * * * /usr/bin/find /tmp -mtime +7 -delete
```

**备选**: 使用独立的 JSON 文件管理，通过自定义脚本桥接 crontab  
**理由**: 直接操作 crontab 更透明，注释标记方式简单可靠，用户 SSH 上去也能看懂。非面板创建的条目不带标记，面板不会碰它们。

### 5. Crontab 读写方式

**选择**: 读取用 `crontab -l`，写入用 `echo "$content" | crontab -` 整体回写

**理由**: crontab 不支持单行编辑 API，整体回写是标准做法。写入前先读取最新内容，只修改面板管理的条目，保留其他行不变。

### 6. 执行历史存储

**选择**: 每个任务一个 JSONL 文件，存于 `data/cron-history/<id>.jsonl`

**格式**:
```json
{"time":"2026-08-17T03:00:00Z","exitCode":0,"stdout":"...","stderr":"...","duration":1200}
```

**备选**: 单一 SQLite 数据库  
**理由**: JSONL 无依赖、追加写入高效、按任务隔离便于清理。每个文件保留最近 50 条，超出时截断。

### 7. "立即执行"实现

**选择**: `child_process.exec(command, { timeout: 60000 })` 同步等待结果，写入历史

**理由**: 计划任务通常是短命令（清理、备份脚本），60 秒超时足够。超时视为失败记录。

### 8. 前端周期选择器

**选择**: 快捷模式 + 高级模式双切换

- 快捷模式：预设选项（每N分钟、每小时、每天、每周、每月）+ 时间选择
- 高级模式：直接编辑 cron 表达式（5 段）
- 底部实时预览生成的 cron 表达式和下次执行时间

**理由**: 覆盖新手和高级用户，宝塔面板也是类似方案。

## Risks / Trade-offs

- **[并发写入 crontab]** → 使用文件锁或简单的内存互斥锁，防止两个请求同时读写 crontab 导致数据丢失
- **[ufw 未安装]** → 首次访问防火墙页面时检测 ufw 是否可用，不可用时展示提示信息而非报错
- **[面板端口变更后规则不同步]** → 面板端口保护基于实时读取配置，不缓存端口号
- **[crontab 格式差异]** → 解析时兼容注释行、空行、环境变量行（SHELL=、PATH= 等），只操作标准 cron 行
- **[sudo 权限]** → 运行面板的用户需要有 ufw 和 crontab 的 sudo 免密权限，安装脚本中配置
