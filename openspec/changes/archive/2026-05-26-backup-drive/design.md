## Context

云备份页面（Sync.vue）目前仅有 WebDAV 连接状态卡片和备份历史表格。用户需要一个本地的备份盘空间，可以手动拖拽上传任意文件作为备份，支持文件管理（下载、删除、重命名、新建文件夹），并且每次修改后自动同步到 WebDAV 云端。

当前系统中：
- `multer` 已安装，可用于文件上传
- `data/drive/` 目录需创建，作为备份盘的本地存储根目录
- rclone WebDAV 连接配置已存在（sync 服务），可复用

## Goals / Non-Goals

**Goals:**
- 在云备份页面提供备份盘卡片，展示独立备份空间
- 支持拖拽/点击上传文件到备份盘（限制单文件 500MB）
- 支持文件下载、删除、重命名、新建文件夹
- 支持目录导航（进入/返回文件夹）
- 每次写操作后自动同步到 WebDAV 的 `worm-panel-backup/drive/` 目录
- 未连接 WebDAV 时备份盘仍可本地使用，同步静默跳过
- 响应式布局，手机端可用

**Non-Goals:**
- 不做备份盘的版本管理或文件历史
- 不做文件夹压缩下载（仅单文件下载）
- 不备份到 WebDAV 以外的存储后端
- 不做上传队列/断点续传

## Decisions

### 1. 分离式路由设计
后端新增独立路由文件 `src/routes/drive.js`，不耦合到现有 sync 路由。
- **理由**: 职责分离，备份盘和云备份是独立概念，各自路由清晰
- **替代方案**: 在 sync 路由中加新端点 → 拒绝，sync 已有 7 个端点，继续膨胀降低可维护性

### 2. 复用 sync 服务的 WebDAV 配置
备份盘同步复用 sync 模块中已保存的 WebDAV 连接配置（webdavUrl/webdavUser/webdavPass）。
- **理由**: 用户只需配置一次 WebDAV 连接，两个功能共享同一份凭据
- **实现**: 从 `config.json` 读取 sync 配置，调用 rclone sync，不创建新的 rclone remote

### 3. 写操作后异步触发同步
上传/删除/重命名/新建文件夹后，frok-and-forget 方式调用 rclone sync，不阻塞 HTTP 响应。
- **理由**: 用户操作体验流畅，不等待云端同步完成
- **失败处理**: 同步失败仅日志记录，不影响本地操作；用户可在备份历史中看到云端同步状态
- **替代方案**: 同步完成后才返回 → 拒绝，大文件上传后等待同步会阻塞用户

### 4. 路径安全校验
后端对所有文件操作路径进行目录穿越检查，确保只能在 `data/drive/` 内操作。
- **实现**: 校验 `path.resolve(driveDir, userPath)` 必须以 `driveDir` 开头
- **不依赖前端校验**: 防止恶意请求直接操作文件系统

### 5. 前端独立于 sync 页面展示
备份盘作为 Sync.vue 中的一个独立卡片区域，不跳转子页面。
- **理由**: 备份盘是云备份页面的自然扩展，保持在同一页面使用户能同时看到云端和本地备份
- **交互**: 文件列表区域可滚动，不占用过多页面空间

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| 大文件上传（接近 500MB）占用内存和带宽 | multer 流式写入磁盘，不缓存到内存；上传期间 UI 显示进度 |
| 同步失败导致云端与本地不一致 | 每次写操作都触发同步，最终一致性；失败仅日志记录 |
| 目录结构嵌套过深 | 限制最大深度（如 5 层），UI 通过面包屑导航 |
| 多人同时操作文件 | 不做文件锁，后写入覆盖前写入（单用户面板，风险低） |
| 文件重名覆盖 | multer 的 `FileFilter` 检查重名时追加时间戳或提示确认 |
