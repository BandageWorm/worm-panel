## Context

当前 `FileBrowser.vue` 使用 Element Plus `el-table` 展示文件列表，数据通过 `GET /api/files` 一次性拉取。面包屑使用 `el-breadcrumb` 实现，仅支持点击段跳转。文本编辑器使用 `vue-codemirror`，桌面端体验良好但移动端字体偏大。

三项改进均在前端完成，不涉及后端 API 改动。

## Goals / Non-Goals

**Goals:**
- 文件列表支持按名称、大小、修改时间点击列头排序（升序/降序切换）
- 面包屑支持切换为路径输入框模式，支持一键复制路径
- 文本编辑器在移动端（≤768px）字号调整为 12px

**Non-Goals:**
- 不涉及服务端排序/分页
- 不改变文件管理后端 API
- 不引入新的前端依赖
- 不改变桌面端编辑器的字号

## Decisions

### 排序：客户端 sortable="custom" + @sort-change 事件

Element Plus 的 `el-table` 内置支持列排序。选择 `sortable="custom"` + 手动处理 `sort-change` 事件而非 `sortable`（自动排序），原因：
- 文件列表包含目录和文件混排，目录优先于文件的排序规则需要自定义
- 手动排序可以保持排序逻辑完全可控

排序规则：目录始终排在文件前面（同类型内再按排序列排序）。

### 面包屑：toggle 模式

用户选择的方案：面包屑模式与路径输入框模式通过按钮切换。
- 默认显示面包屑，右侧放置"编辑路径"按钮（✏️）和"复制路径"按钮（📋）
- 点击 ✏️ → 面包屑隐藏，显示 `el-input`，预填当前路径
- 按 Enter 或点击跳转 → 验证路径有效性 → 导航 → 切回面包屑
- 点击 📋 → `navigator.clipboard.writeText()` 复制当前路径

不采用双行显示，因为 768px 以下宽度有限，双行会压缩表格空间。

### 编辑器移动端字号：CSS media query

直接在 `FileBrowser.vue` 的 scoped style 中追加 @media 规则，覆盖 `.cm-editor` 的字体大小。无需修改 Codemirror 配置。

## Risks / Trade-offs

- **客户端排序仅对当前目录有效** — 用户若期望全局搜索排序需要后端支持，当前不做。这是合理的渐进，后续可按需添加后端分页排序。
- **路径输入框不做自动补全** — 简化实现，用户需输入完整正确路径。若输错路径，后端返回 404，前端提示错误。
- **移动端 12px 对部分用户可能偏小** — 但在手机屏幕宽度有限的情况下，12px 是代码阅读的合理折中。
