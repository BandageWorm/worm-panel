## Context

文件管理模块当前支持目录浏览、上传、下载、删除、新建目录。需要增加文本文件编辑能力，使用户可以直接在面板中查看和修改服务器上的文本文件。

现有架构：
- `FileBrowser.vue` — 文件列表展示 + 操作按钮
- `src/services/files.js` — 后端业务逻辑，`safeResolve()` 防路径穿越
- `src/routes/files.js` — Express 路由，所有 API 挂载在 `/api/files` 下，JWT 认证

## Goals / Non-Goals

**Goals:**
- 后端提供读取和保存文本文件的 API
- 前端集成 CodeMirror 6 代码编辑器，弹窗形式编辑文本文件
- 根据文件扩展名自动切换语法高亮模式
- 支持编辑后保存，保存成功后自动关闭弹窗并刷新列表

**Non-Goals:**
- 不做大文件编辑（>1MB 文件提示只读打开或拒绝）
- 不做二进制文件检测和编辑
- 不做文件重命名/移动
- 不做版本历史或自动备份
- 不做文件新建功能
- 不做拖拽上传增强

## Decisions

### 1. 编辑器方案：CodeMirror 6

考虑过 Monaco Editor（VS Code 内核）和 CodeMirror 6，选择 CodeMirror 6 的理由：
- 体积更小（~200KB gzip vs Monaco ~2MB），适合轻量面板
- 通过 `vue-codemirror` 可以方便集成到 Vue 3
- 语言包按需加载，仅加载常用语法
- 对于服务器配置文件编辑场景完全够用

### 2. API 设计：独立 read/write 端点

不通过已有的 `GET /api/files/download` 来读取文本，因为：
- download 接口是流式二进制传输，不适合前端直接获取文本内容
- 独立 `read` 接口返回 `{ content }` JSON 结构，前端可直接绑定到编辑器
- `write` 接口使用 PUT + JSON body，语义清晰

### 3. 文件编码处理

统一使用 UTF-8 编码：
- 读取时以 UTF-8 解码，若失败则拒绝操作
- 保存时以 UTF-8 写入
- 不处理 GBK/GB2312 等编码，如遇编码错误返回明确错误提示

### 4. 可编辑文件类型判断

通过文件扩展名白名单判断是否可编辑：
- 编辑器语言模式映射表来决定语法高亮
- 不在映射表中的扩展名统一视为纯文本或拒绝编辑
- 无扩展名的文件允许以纯文本打开

### 5. UI 交互

- 操作列新增"编辑"按钮，仅对匹配白名单的文件显示
- 点击按钮弹出 el-dialog，宽度 90%，高度 80vh
- 弹窗加载时显示 loading，内容加载完成后初始化 CodeMirror
- 保存按钮调用 write API，成功则关闭弹窗 + ElMessage.success + 刷新列表

## Risks / Trade-offs

- [大文件性能] 用户可能尝试编辑大文件（如日志）→ 读取时检查文件大小，超过 1MB 提示不可编辑或只读预览
- [并发编辑覆盖] 多人同时编辑同一文件，后者覆盖前者 → 当前不做锁机制，属于可接受范围（管理面板通常单人使用）
- [XSS 风险] 文件内容可能包含恶意脚本 → CodeMirror 是纯文本渲染，不执行内容，无 XSS 风险
- [编码问题] 非 UTF-8 文件（如GBK编码的配置文件）→ 读取失败时提示用户，不做自动转码
