## Why

现有文件管理模块只覆盖了浏览、上传、下载、删除、新建目录、在线编辑这几项基础操作，缺失了文件管理器"天经地义该有"的动作：重命名、移动、复制、新建空文件。想改个配置名或整理文件，只能"下载 → 删除 → 改名 → 重传"，非常别扭。此外删除目录要求必须为空，代理机上常见的部署目录、`node_modules` 无法一键清理；上传的 `tar.gz`/`zip` 压缩包无法在线解压；脚本无法在线 `chmod +x`。本次变更把这些补齐，让文件管理达到"文件管理器该有的样子"。

## What Changes

- **新增重命名**：重命名文件或目录（同目录内改名）。
- **新增移动/复制**：将文件或目录移动或复制到目标路径（支持跨目录）。
- **新增新建空文件**：在当前目录创建一个空文本文件。
- **递归删除**：删除目录时支持递归删除非空目录（**BREAKING**：现有"目录不为空则拒绝删除"的行为改为可递归删除，前端需二次确认）。
- **新增解压/压缩**：解压 `.tar`、`.tar.gz`/`.tgz`、`.zip` 到指定目录；将文件或目录压缩为 `.tar.gz` 或 `.zip`。
- **新增权限修改**：修改文件/目录的权限位（chmod，八进制），当前权限列从"只读展示"变为"可编辑"。
- **新增批量操作**：前端支持多选，批量删除、批量移动。
- **新增文件搜索/过滤**：当前目录内按文件名过滤。
- **前端 UI 增强**：文件行操作菜单新增重命名/移动/复制/压缩/权限入口，工具栏新增新建文件、搜索框、批量操作栏。

权限边界策略：能用 Node `fs` 完成的操作（重命名、移动、复制、递归删除、新建文件）走 `fs`；必须调用系统命令的操作（解压/压缩、chmod 在权限不足时）走 `execFile` + 权限不足自动 `sudo` 重试，与 firewall/nginx 模块保持一致。

**做什么**：在现有 `file-browser` 能力上补齐常规文件管理动作及其 UI。
**不做什么**：不做文件内容搜索（grep 全文）、不做回收站/软删除、不做文件共享/直链（已有独立的"文件直链"模块）、不做远程/跨主机文件传输、不做符号链接的高级管理。

### Modified Capabilities
- `file-browser`: 新增重命名、移动、复制、新建空文件、递归删除、解压/压缩、权限修改、批量操作、文件名搜索等需求，并相应扩展文件管理页面 UI 需求。

## Impact

- **后端代码**：
  - `src/services/files.js`：新增 rename/move/copy/newFile/递归删除逻辑；新增 extract/compress（execFile + sudo 重试）；新增 chmod（fs 优先，权限不足走 sudo）。
  - `src/routes/files.js`：新增对应路由（rename、move、copy、newfile、extract、compress、chmod、batch-delete、batch-move）。
- **前端代码**：
  - `client/src/components/FileBrowser.vue`：操作列/工具栏扩展，新增对应弹窗与批量选择列、搜索框。
  - `client/src/api/index.js`：如有需要补充调用方法。
- **依赖**：解压/压缩优先复用系统 `tar`/`unzip`/`zip` 命令，避免新增 npm 依赖；若目标环境缺失则在 UI 提示。
- **安全**：所有路径继续走 `safeResolve` 校验（绝对路径 + 敏感系统路径拦截）；exec 类操作使用 `execFile`（参数数组，避免命令注入）；递归删除、批量删除前端强制二次确认。
